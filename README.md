## Что сделано

Выполнен аудит безопасности, устранены следующие уязвимости:

- **XSS** — убрано использование `dangerouslySetInnerHTML` при выводе пользовательских данных в админке и профиле.
- **CSRF** — на все небезопасные методы (POST/PATCH/DELETE) добавлена double-submit cookie защита.
- **NoSQL-инъекции** — добавлена валидация всех входных данных через `celebrate`/Joi, защита от передачи объектов в фильтры, экранирование пользовательского ввода в регулярных выражениях.
- **Переполнение буфера** — установлены лимиты на размер тела запроса (`1mb`) и загружаемых файлов (`5mb`), добавлены ограничения длины полей в Joi.
- **ReDoS** — переписано небезопасное регулярное выражение для телефона, применено экранирование пользовательских строк перед `new RegExp`.
- **DDoS** — подключён `express-rate-limit` (100 запросов в минуту на IP) и `helmet` для безопасности HTTP-заголовков.
- **Path Traversal** — исправлена раздача статики (нормализация пути + проверка на выход из директории), имена загружаемых файлов генерируются на сервере.
- **Пароли** — заменено небезопасное хеширование md5 на `bcrypt`.
- **Аудит зависимостей** — проведён `npm audit`, обновлены уязвимые пакеты.
- **Линтер** — все ошибки и предупреждения ESLint устранены.
- **Нагрузочное тестирование** — проверена устойчивость при 110 одновременных запросах: срабатывает rate-limit (429).
